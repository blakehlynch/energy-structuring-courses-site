Volatility estimation and cases

Learning objectives

  • Apply the four-step real options process.
  • Estimate project volatility by Monte Carlo and explain why it differs from input volatilities.
  • Know when to keep uncertainties separate.
  • Structure a staged development as compound options.

Prerequisites

  • Modules 1–4.

A four-step process

Copeland and Antikarov describe the process they use with clients. Copeland & Antikarov ch.8 (pp.219–222)

  1. Base-case DCF. Value the project without flexibility in the usual way.
  2. Event tree. Model how that value evolves under uncertainty, without decisions. The tree must reproduce step 1's value.
  3. Decision tree. Add management's choices at the nodes (defer, expand, abandon, switch).
  4. Value the decision tree by replication or risk-neutral probabilities.

Two assumptions make this practical. The marketed asset disclaimer (MAD) treats the project's own present value without flexibility as the underlying asset, as if it traded, which removes the need for a twin security. Samuelson's theorem says that if cash-flow expectations are properly anticipated, changes in value follow a random walk, whatever the pattern of the cash flows. Many correlated, even mean-reverting, input uncertainties can therefore be combined into one random walk in project value. Copeland & Antikarov ch.8 (pp.219–223)

Consolidated volatility by Monte Carlo

The volatility that drives the tree is the volatility of the project's return, not of the price or any other input. Copeland and Antikarov simulate the DCF spreadsheet with the uncertain inputs (prices with autocorrelation, quantities correlated with price, costs correlated with quantity). For each draw they compute the one-year return on project value, \(z = \ln\big((PV_1 + FCF_1)/PV_0\big)\), and use the standard deviation of \(z\) as the lattice volatility. Copeland & Antikarov ch.9 (pp.245–250) In their example a 10% price uncertainty became a 21% project volatility, because operating leverage and persistent shocks amplify input uncertainty. Copeland & Antikarov ch.9 (p.250) The lattice then pays out each period's free cash flow as a proportion of value, so the tree still recombines. Copeland & Antikarov ch.9 (pp.251–252)

Worked example 1 · project volatility from price uncertaintyChecked by code

A 7-year project. Prices fall from $10 to $8.80, volumes grow from 100 to 158 units, unit costs fall from $6 to $3.60, fixed costs are $60 a year and WACC is 12%. Year-1 price is uncertain with a 10% (lognormal) standard deviation, and shocks persist with autocorrelation 0.9. We run 4,000 draws.

PV₀ = $2,624.28; at a $2,400 cost, NPV = $224.28 project volatility = 17.1% (price volatility 10%); with no persistence (ρ = 0) only 3.4%

Persistence is what matters. A one-off price shock barely moves a seven-year value, while a persistent one moves the whole stream, amplified by operating leverage. Getting autocorrelation right matters as much as the input volatility itself. Copeland & Antikarov ch.9 (pp.248–250) Synthesis

Worked example 2 · the same project with a three-year windowChecked by code

Using PV₀ = $2,624 and σ = 17.1% from Example 1, a $2,400 cost, r = 5%, a 10% payout rate and the option to start any time in the next three years:

NPV of starting now: $224.28; value with the option to defer: $278.53

The flexibility is worth about $54 here. The payout rate is high, because waiting costs a year of cash flow, which makes early exercise attractive and keeps the option value moderate. Synthesis

When to keep uncertainties separate

Consolidation fails when decisions depend on a particular uncertainty. A drilling decision depends on what the well reveals about reserves, not just on total value. Copeland and Antikarov keep such uncertainties separate in "rainbow" options. Learning options combine technical uncertainty, which falls as you invest to learn, with market uncertainty, which grows over time. Copeland & Antikarov ch.8 (p.221) Finnerty's North Sea field is the energy version. Reserve size is resolved stage by stage through test and appraisal drilling, oil price uncertainty is modelled on a lattice built from futures, and the field is valued by working back from the production decision across both. Finnerty ch.12 (pp.217–220) Finnerty values the field at several oil-price volatilities to show how price uncertainty drives its option value, and notes that crude futures let the sponsors both assess and hedge that risk. Finnerty ch.12 (p.219)

Common pitfalls

  • Using the wrong volatility. Price or equity volatility is not project volatility. Model the project. Copeland & Antikarov ch.9 (p.244)
  • Forgetting payouts. Without them, deferral is never exercised early and option values are inflated. Copeland & Antikarov ch.5 (pp.124–125)
  • Adding options. Value interacting options together (Module 2). Synthesis
  • Market price of risk. Where futures exist, use them for the risk-neutral path. Otherwise estimate the market price of risk from correlation with the market, or treat it as zero if the risk is genuinely diversifiable. Hull ch.36 (pp.782–784)
ALM analogy

Consolidated volatility is the economic-capital practice of running many risk drivers through a cash-flow model and reading off the distribution of a single value metric, rather than adding the input volatilities. As with embedded-value sensitivities, persistence and leverage turn a small input shock into a large value shock, and a "one-year VaR" on a long book depends almost entirely on how shocks propagate. Dated: tools and examples

Copeland and Antikarov's spreadsheets use Crystal Ball (2001), and Finnerty's field example uses 2000s fiscal terms. Today Python or R Monte Carlo is standard, and decision-tree and lattice software is widely available. Energy transition adds new sources of uncertainty to model separately: carbon prices, policy and technology learning curves. Outside the texts

Going deeper: why Samuelson's theorem lets you use one tree

Suppose a project's cash flows are expected to decline, mean-revert or cycle. If investors know the expected path, the current value already reflects it, and value changes only when expectations change. Those changes are news and therefore unpredictable, so value follows a random walk even when the cash flows themselves are highly predictable in pattern. Copeland & Antikarov ch.8 (pp.222–224) This is what licenses a single lognormal tree on project value. It applies to the value, not to prices: mean-reverting commodity prices (Course 6) still produce random-walk changes in the value of claims on them. Synthesis

Key takeaways

  • Four steps: DCF, event tree, decision tree, valuation. The event tree must reproduce the DCF value.
  • MAD and Samuelson's theorem justify a single tree on project value.
  • Estimate project volatility by simulating the cash-flow model. Persistence and leverage dominate.
  • Keep uncertainties separate when decisions hinge on them, as in staged exploration and learning options.
